BeeZigUi: improvements to make

Bugs, performance and API problems found in BeeZigUi (Zui) on 2026-11-14, and what has been done about each: while moving BeeModel's dialogs onto it (milestones M0 and M1 of BeeModel's Docs/beezigui-migration.html), and in a review of the whole library in four parts (core; widgets; drawing and the renderers; backends and add-ons). Every item names the code, says what goes wrong, and says how sure it is. Most were reproduced: the tests are in Docs/repro/ (Docs/repro/run.sh runs them; a failing or panicking test there is the problem still being there).

Where it stands

2026-11-14, after the first round of work: every crash and every bug rated high or medium is fixed, with a regression test (tests/regress_test.zig, named by item id, plus tests in backends/software.zig, backends/wayland.zig, backends/wayland/keymap.zig, src/overlay.zig, src/font.zig and tests/files_test.zig). The software renderer prototype is in (bench frame 2267 → ~700 µs, node graph 10.5 → 4.3 ms, pixel-identical in BeeModel's scenarios). What is open or partial is listed with the status filter; the notes say what is missing. The order below was the plan for this round.

Checks run after the work: BeeZigUi's tests, scenarios, docs check and gl-check; BeeModel's 325 scenarios, its unit tests and zig build test-ui. In BeeModel (release, 1280×800, same core) the Zui dialogs got about twice as fast: Preferences 2.21 → 1.09 ms, Keymap 2.43 → 1.18, Undo History 1.35 → 0.79, Shortcuts 2.00 → 0.95.

Order of work (first round)

  1. Crashes first (C1–C6): small, local fixes; each is a panic in Debug, and most are undefined behaviour in ReleaseFast.
  2. The software renderer (P1–P5): a prototype exists (Docs/repro/render/sw2.zig). On the bench frame it renders in 689 µs instead of 2267 µs, and the node bench in 7.5 ms instead of 10.5 ms, with 0 pixels different (checked again for this list: Docs/repro/run.sh bench). A modal dialog's backdrop drops from 850 to 70 µs. This is BeeModel's biggest frame-time win: its Zui dialogs cost 0.3–0.5 ms more than its own did.
  3. Input and Escape ownership (B1–B5, A12): BeeModel works around B1 today (zuihost.shown()) and will meet B2, B3 and B5 in its Preferences and forms.
  4. Before the BeeModel milestones that need them: M2 property panels: B6 (typed values), B8 (layout that never shrinks). M3 lists: C2 (Shift+click crash), L4 (UTF-8 in renames), L5 (long drag kinds). M4 menus: P10 (palette). M5 text: P9, P11, L3, L9. M7 docking: B9 (dock overflow), A13 (detached windows on the app's connection). M8 node editor: P6, P7, B12 (glyph cache).
  5. The Wayland backend (H1, C5, B9–B11) and the script player (C6): matters for Zui's own native programs; BeeModel keeps its own Wayland client.
  6. The rest, as time allows. Fixed items move to the bottom list with the date.
